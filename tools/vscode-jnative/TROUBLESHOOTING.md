# JNative VS Code 插件故障排查（中文）

作者：张晓达

## 状态栏含义

| 显示 | 含义 | 可执行操作 |
|------|------|------------|
| `JNative LS` 旋转 | 正在启动 | 等待；过久则点状态栏看日志 |
| `JNative LS` 勾 | 就绪 | 正常编辑 |
| `JNative LS` 错误底色 | 失败/意外停止 | 「查看日志」/「重启语言服务」 |
| 斜杠图标 | 未启用或未信任 | 信任工作区或打开 `jnative.enableLanguageServer` |

## 常见问题

### 1. 没有补全 / 跳转

1. 确认扩展版本 ≥ **0.6.0**，且 `jnative.jarPath` 指向**当前**仓库 `target/jnative.jar`（与 CLI `jnative --version` 一致）。
2. 命令面板 → **JNative: 显示语言服务日志**，是否有 `started OK` / `analyzeUnits`。
3. `.java` 仅在已识别 JNative 项目源码根内才会切到 `jnative` 语言；普通 Java 项目不会被接管。
4. **JNative: 重启语言服务**（有频率限制，防止崩溃循环）。

### 2. 语言服务反复退出

自动重启最多约 3 次/分钟。超出后需手动重启并检查：

- `jnative.jarPath` / `executablePath` 是否失效
- Java 是否可运行 `java -jar … lsp`
- 日志中的协议/异常（不会打印密钥或完整环境变量）

### 3. 构建失败但看不懂

- **源码错误**：Problems 可点击定位；通知提供「查看 Problems」
- **工具/链接错误**（缺 clang 等）：输出通道 `[tool]`，**不会**伪造到用户文件第 1 行
- **超时**：提示构建超时，不视为成功，不启动旧程序
- **取消选择项目**：明确「已取消」，不构建

### 4. 重命名被拒绝

预期行为（不是故障）：

- 可覆盖的非 private 实例方法
- 第三方 `pkg-cache` / 只读路径
- 构造器、名称冲突、分析结果与源码不一致

### 5. 格式化失败

语法/词法错误时**拒绝写回**，避免损坏文件。先修错误再格式化。

### 6. 未信任工作区

不会启动编译器、LSP、构建或运行。信任后再用。

### 7. 卸载后仍有 `java … lsp` 进程

停用/卸载应触发 `deactivate` → 停止 LS。若残留：活动监视器结束对应 `java -jar … lsp`，并确认已升级到会正确 `stop()` 的版本。

## 日志位置

- `JNative Language Server` 输出通道（LSP stderr，有界）
- `JNative` 输出通道（构建/运行）
