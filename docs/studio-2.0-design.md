# JNative Studio 2.0 设计方案

作者：张晓达

目标：把 Studio 从“带窗体设计器的小编辑器”升级为可以日常开发 JNative 全部项目类型（桌面 App、Web、移动、服务端、库）的完整 IDE，
体验对标 Xcode（导航器 / 编辑器 / 检查器 / 调试区、运行目标、设计器）和 IntelliJ IDEA（智能感知、代码检查、重构、Search Everywhere、意图操作）。

## 1. 现状与差距

| 领域 | Studio 1.x 现状 | 差距（对标 Xcode / IDEA） |
| --- | --- | --- |
| 补全 | `IdeComplete`：按文本建的轻量索引，不做类型推断 | 泛型 / 重载 / lambda 参数推断不准；无返回类型与参数名的完整信息 |
| 参数提示 | 无 | 方法调用处没有 Parameter Info（当前参数高亮、重载切换） |
| 快速文档 / 类型信息 | 只有编译错误的悬停 | 没有“光标处符号的类型、签名、返回值、所在类” |
| 代码检查 | 只有编译器错误 / 警告（`analyze --project`） | 没有未使用变量 / 导入 / 私有成员、不可达代码、空 catch、字符串 `==`、永真条件等静态检查；没有快速修复（Alt+Enter） |
| 导航 | 轻量索引跳转（⌘D）、转到符号 / 文件 | 没有查找用法（Find Usages）、类型层次、调用层次、文件结构面板、面包屑 |
| 重构 | 重命名（文本级）、重新缩进 | 没有语义级重命名、提取方法 / 变量、内联、修改签名、移动类、优化导入 |
| 调试 | 无（仅有 `--debug` 构建与 VS Code + CodeLLDB 教程） | 没有断点、单步、变量 / 调用栈 / 线程 / 表达式求值、条件断点、异常断点 |
| 项目类型 | 窗体应用 + 控制台 | Web（browser + server + shared）、移动（Android / iOS）、库、多模块都只能手写配置、命令行构建 |
| 运行 | ⌘R 生成并运行一个目标 | 没有运行配置（参数 / 环境变量 / 工作目录）、目标设备选择、多进程（dev server + 浏览器） |
| 测试 | 无 | 没有测试发现 / 运行 / 结果树 / 覆盖 |
| 版本控制 | 无 | 没有 Git 状态、差异、提交、分支 |
| 编辑器 | 高亮、智能编辑、查找替换、平滑滚动 | 没有代码折叠、多光标、分栏、书签、TODO 面板、内联错误说明、Inlay Hints |

后端已有的能力（本方案的出发点，**不重复造轮子**）：

- `jnative lsp`：完整的 LSP 服务（completion、signatureHelp、hover、definition、references、documentSymbol、workspaceSymbol、
  codeAction、rename、formatting、publishDiagnostics），基于编译器语义分析，实测每次请求约 0.2 s，整项目分析约 0.5 s。
- `jnative analyze --project`：整项目前端检查（Studio 1.x 在用）。
- `jnative build --debug`：生成 DWARF 调试信息和 `*.jn-debug.json`，`lldb` / `lldb-dap` 已随 Xcode 提供。
- `jnative build --target wasm32-browser`、`jnative dev`（浏览器 + 服务端联调）、`jnative mobile build|devices|run|logs|stop`。

## 2. 总体架构

```
┌──────────────────────────── Studio 2.0（JNative 原生 GUI 外壳）────────────────────────────┐
│ 导航器 │ 编辑器区（多标签/分栏） │ 检查器（属性/文档/问题） │ 底部：输出/问题/调试/终端/测试   │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│                              服务总线（异步请求、回调在 UI 线程）                               │
├──────────────┬───────────────┬────────────────┬───────────────┬──────────────────────────────┤
│ 语言服务客户端 │ 构建服务       │ 调试服务        │ 运行/设备服务  │ 项目模型 / 运行配置 / VCS / 测试  │
│ (LSP over     │ (jnative build │ (DAP over       │ (进程、dev     │                              │
│  stdio)       │  流式输出)      │  lldb-dap)      │  server、mobile)│                              │
└──────┬───────┴───────┬───────┴────────┬───────┴───────┬───────┴──────────────────────────────┘
       ▼               ▼                ▼               ▼
  jnative lsp     jnative build    lldb-dap + DWARF   jnative dev / mobile / 本机进程
```

要点：

1. **一个长驻的语言服务进程**（`jnative lsp`，每个打开的项目一个），Studio 作为 LSP 客户端；编辑时做全量同步（`textDocument/didChange`，防抖），
   诊断、补全、参数提示、悬停、定义、引用、重命名、格式化、代码操作全部走它。轻量索引 `IdeComplete` 保留为服务未就绪 / 崩溃时的降级。
2. **调试走 DAP**：Studio 作为 DAP 客户端启动 `lldb-dap`，用 `jnative build --debug` 的产物与 `*.jn-debug.json`（把 JNative 对象 / 数组 / 字符串映射成可读变量）。
3. **运行目标抽象**：`RunTarget = 项目目标 × 平台（本机 / 浏览器 / Android 设备或模拟器 / iOS 模拟器） × 配置（Debug / Release） × 参数`；工具栏像 Xcode 一样选择 Scheme 与目标。
4. **所有后台工作异步**：Studio 是单线程 UI，子进程 I/O 用定时器轮询（已有 `IdeProc`）；LSP 客户端同样基于“非阻塞读 + 定时泵”，请求带序号，结果回调在 UI 线程，过期结果（文档版本已变）丢弃。
5. **能力协商与降级**：任一服务不可用（找不到 `java` / `lldb-dap` / 设备）时给出可操作的提示，不影响编辑。

## 3. 功能模块设计

### 3.1 代码智能（语言服务）

- **补全**：以 LSP 为准，列表项显示 *图标 + 名称 + 参数摘要 + 右侧返回类型*；方法补全插入 `name(` 并在有参数时立即弹出参数提示；重载分别列出；已导入 / 未导入类型提示自动加 `import`（后续）。
- **参数提示（Parameter Info）**：输入 `(` 或 `,`、或 ⌘P 触发；在调用位置上方（空间不足时下方）显示签名 `返回类型 方法名(参数类型 参数名, …)`，当前参数加粗；光标移出调用括号或按 Esc 关闭；重载用 ↑/↓ 切换（后续）。
- **快速文档 / 类型信息**：⌘J（Quick Documentation）或鼠标悬停 0.5 s 显示符号签名、返回类型、所属类 / 文件；表达式类型（⌃⇧P，后续）。
- **Inlay Hints（后续）**：参数名提示、`var` 推断类型。
- **签名 / 语义高亮（后续）**：区分局部变量、字段、静态成员、未使用变量（灰色）。

### 3.2 代码检查（Inspections）与快速修复

放在**编译器内**（`io.jnative.inspect`），作为 `analyze` / LSP 诊断的“警告”输出，所以 Studio、VS Code 扩展、命令行都受益。每条检查有稳定的诊断代码，可配置级别（错误 / 警告 / 弱警告 / 关闭），可在行尾用 `// noinspect: CODE` 抑制。

第一批（第 1 阶段交付）：

| 代码 | 检查 | 级别 |
| --- | --- | --- |
| `W001` | 局部变量（含 foreach 变量）未使用；方法参数暂不检查 | 警告 |
| `W002` | 变量赋值后从未被读取 | 弱警告 |
| `W003` | `import` 未使用 | 警告 |
| `W004` | 私有字段 / 方法未使用 | 警告 |
| `W005` | 不可达代码（`return` / `break` / `continue` / `throw` 之后） | 警告 |
| `W006` | `catch` 块为空 | 警告 |
| `W007` | 用 `==` / `!=` 比较字符串 | 警告 |
| `W008` | 条件恒为真 / 恒为假（字面量） | 警告 |
| `W009` | 局部变量遮蔽字段（已实现，默认关闭：构造器/setter 惯用写法误报多） | 弱警告 |
| `W010` | 自赋值 `x = x` | 警告 |

第二批：未处理的返回值、可简化的条件、整数除法精度、`switch` 缺 `default`、可见性可收紧、重复代码块、命名规范、循环里的字符串拼接性能提示、资源未关闭等。

快速修复（Alt+Enter / 灯泡）：删除未使用变量 / 导入、`==` 改 `.equals`、给空 `catch` 加注释、创建缺失的方法 / 类 / 字段、添加 `import`、实现接口方法、`@Override` 提示等；通过 LSP `codeAction` 提供。

### 3.3 导航与结构

- Find Usages（⌥F7）、转到定义（⌘D / ⌘点击，LSP 精确）、转到实现 / 类型（后续）。
- 文件结构面板（⌘F12）、面包屑、转到符号（⌘T 全局，走 `workspace/symbol`）。
- Search Everywhere（双击 ⇧）：文件 / 类 / 符号 / 动作 / 设置 一个入口。
- 类型层次（⌃H）、调用层次（后续）。
- TODO / FIXME 面板。

### 3.4 重构

语义级重命名（LSP `rename`，项目内所有源与 `.jnui` 控件名）、提取方法 / 局部变量、内联、修改签名、移动 / 重命名类（同步文件）、优化导入（⌃⌥O）、格式化文件 / 选区（`formatting`）。每个重构先预览影响范围，再一次性应用，可一次撤销。

### 3.5 调试器

- **断点**：行断点（编辑器边栏点击）、条件 / 命中次数 / 日志断点、异常断点、函数断点；断点集合持久化，随项目保存。
- **控制**：继续 / 暂停 / 单步跳过 / 步入 / 步出 / 运行到光标处 / 停止。
- **调试区（Xcode 式）**：变量（把 JNative 字符串、数组、`ArrayList`、对象字段展开为可读树，依据 `*.jn-debug.json`）、调用栈（点击跳转源码）、线程、监视表达式、调试控制台（lldb 命令与表达式求值）。
- **编辑器内联**：当前执行行高亮，变量值内联显示；悬停变量显示值。
- **实现**：`jnative build --debug` → 启动 `lldb-dap`（DAP：`initialize / launch / setBreakpoints / threads / stackTrace / scopes / variables / evaluate / continue / next / stepIn / stepOut / disconnect`）；Studio 内置最小 DAP 客户端（Content-Length 帧 + JSON）。
- **Web 调试（后续）**：wasm 的源码映射与浏览器 DevTools 联动（`docs/developer/WASM_SOURCE_DEBUG.md`）；服务端端点沿用原生调试。
- **移动调试（后续）**：Android（`lldb` + `adb`）、iOS 模拟器（`lldb` 附加）。

### 3.6 项目类型与运行配置

| 项目类型 | 模板 | 运行 / 调试 |
| --- | --- | --- |
| 桌面应用（窗体） | 窗体 + 事件 + Main（已有） | ⌘R 本机运行；⌘Y 调试 |
| 控制台 / 库 | 已有 / 新增库模板（含单元测试） | 运行；测试 |
| Web 应用 | `shared` + `browser`（wasm32-browser）+ `server` 三模块；HTML / CSS / 资源文件编辑 | “Web 全栈”配置：`jnative dev`（服务端 + 浏览器热更新），点“运行”自动打开浏览器；服务端断点调试 |
| 移动应用 | Android / iOS 模板（沿用 `jnative mobile`） | 设备管理器（`mobile devices`）、选择模拟器 / 真机，运行 / 日志（`mobile logs`）/ 停止 |
| 服务端 | `server` 模块模板（路由、数据库示例） | 运行 + 日志面板；端口占用检测 |

运行配置（`.jnative/studio/run.json`）：名称、目标、平台、参数、环境变量、工作目录、构建前步骤；工具栏下拉像 Xcode 的 Scheme；一个项目可保存多份。

多模块项目在导航器里按模块分组，识别 `jnative.project` / `jnative.toml`，提供依赖图、添加依赖（`jnative add`）、包管理器入口。

### 3.7 UI 布局（参考 Xcode / IDEA）

- 顶部工具栏：运行 / 停止 / 调试、Scheme 与目标选择、构建状态（活动指示）、错误 / 警告计数、Search Everywhere。
- 左侧导航器（可切换）：项目文件、符号、查找结果、问题、断点、测试、版本控制。
- 中间编辑器区：多标签 + 分栏（左右 / 上下）、面包屑、边栏（行号、断点、折叠、Git 变更条、诊断图标）。
- 右侧检查器：窗体设计器属性 / 快速文档 / 文件信息（可折叠）。
- 底部：输出、问题、调试、终端、测试结果。
- 外观：浅 / 深色主题、可配置字体与键位（IDEA / Xcode 键位预设）。

### 3.8 其它

- **测试**：识别 `@Test` 方法与 `jnative test`，边栏运行图标、结果树、失败跳转。
- **Git**：状态（文件树着色）、差异视图、提交 / 推送 / 拉取、分支切换（调用系统 `git`）。
- **终端**：内置终端面板。
- **设置**：编译器路径、JDK、代码风格、检查级别、键位。
- **稳定性**：崩溃恢复（未保存缓冲区落盘）、服务进程守护与重启、慢请求超时。

## 4. 实施路线

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **P1 语言服务基础** | 运行时：子进程 stdin 管道（`ProcessBuilder.pipeStdin` / `Process.writeStdin`）；Studio `IdeLsp`（帧 / JSON / 请求路由）；**参数提示**、**快速文档（含返回类型）**、补全项显示返回类型；编译器 **第一批检查 W001–W010** 接入问题面板与波浪线 | 在 `mac-paint`、Studio 自身上，调用方法时弹出参数提示且当前参数高亮；悬停显示签名与返回类型；各检查在示例工程里命中且无误报；端到端测试通过 |
| P2 导航与重构 | Find Usages、文件结构面板、Search Everywhere、语义重命名、优化导入、Alt+Enter 快速修复、格式化走 LSP、代码折叠 | 重命名跨文件正确；查找用法与编译器引用一致 |
| P3 调试器 | DAP 客户端、断点边栏、控制栏、变量 / 调用栈 / 线程 / 控制台、条件断点、内联值 | 在 `examples/debug` 与 `mac-paint` 上设断点、单步、看变量、改变量、求值 |
| P4 项目类型与运行配置 | 运行配置与 Scheme、Web 全栈模板与 `dev` 集成、移动设备管理与运行、服务端模板、依赖管理界面 | 新建 Web 项目一键运行并在浏览器打开；模拟器上运行移动示例 |
| P5 工程效率 | 测试运行器、Git、终端、分栏、书签、Inlay Hints、主题 / 键位预设 | 日常开发闭环不需要离开 Studio |

每个阶段结束都更新 `tools/jnative-studio/README.md`，并在 `StudioPlatformEndToEndTest` 中补自动化验收。

## 5. 风险与对策

- **Studio 是用 JNative 子集写的**（无嵌套类、无 `super`、无复杂泛型）：重逻辑放进编译器 / LSP（完整 Java 实现），Studio 只做 UI 与协议客户端。
- **UI 单线程**：服务调用全部异步 + 版本号去抖；超时与取消。
- **LSP 内存与启动开销**：一个项目一个进程，按需启动，空闲退出；失败时降级到轻量索引。
- **lldb-dap 仅 macOS / Xcode 自带**：调试功能先限 macOS，Linux 用 `lldb` 同协议；缺失时给安装提示。
- **误报**：检查按“宁缺毋滥”先保证精度，带抑制注释与分级开关。
