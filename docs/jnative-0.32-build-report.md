## 1. Architecture

```
Source → Parser → Semantic Model → Annotation Discovery
  → Processor Scheduler → Compile-Time Model API
  → Generated Source / Resource / Metadata
  → Incremental Semantic Pass → IR → Optimizer → LLVM / WASM
```

## 2. Compile-Time Model

Stable types: `ProgramModel`, `ClassModel`, `MethodModel`, `FieldModel`, `ParameterModel`,
`AnnotationModel`, `TypeId`, `TypeReference` (via `TypeId`), generics-aware field/method types.

## 3. Compiler Extension API

Package `io.jnative.meta` is the formal **JNative Compiler Extension API** (`MetaApiVersion.CURRENT = 1`).
Processors must not depend on Parser AST internals, LLVM, or optimizer private tables.

## 4. Annotation Model

Marker annotations discovered at parse time (`CompilationUnit.typeAnnotations` / `fieldAnnotations`).
Meta markers: `@Json`, `@GenerateJson`, `@JsonField`, `@Validated`, `@NotBlank`, `@Min`, `@Max`,
`@Config`, `@Default`, `@Command`, `@Option`, `@Service`, `@Inject`, `@Entity`, `@Id`,
`@Repository`, `@Controller`, `@Get`, `@Post`, plus existing `@Rpc` family.

## 5. Retention

`RetentionPolicy`: `SOURCE`, `COMPILE_TIME` (default), `RUNTIME_METADATA` (selected schema only — not JVM reflection).

## 6. Processor API

`AnnotationProcessor`: `supportedAnnotations()`, `process(ProcessingContext)`, `kind()`, permissions, API bounds.

## 7. ProcessingContext

Exposes: `ProgramModel`, `RoundEnvironment`, `CodeGenerator`, diagnostics, target, deterministic flag,
options, permission checks, previous fingerprints, generated-root reuse.

## 8. CodeGenerator

`CodeGenerator` + `SourceFileBuilder`; escape hatch `createSourceFile` / `createResource` / `createMetadata`.

## 9. Generated Source

Preferred output. Merged into compile unit (`BEGIN GENERATED META`) → normal semantic → IR.

## 10. Generated Resources

Supported via `GeneratedArtifact.Kind.RESOURCE`.

## 11. Generated Metadata

Schemas under `schema/*.json` (JSON / SQL / RPC). Indexed in `generated-index.tsv`.

## 12. Origin Tracking

Each artifact records: processor, version, origin source, origin symbol, input fingerprint, output hash.
Header comments: `generated by` / `origin` / `fingerprint`.

## 13. Incremental Processing

Previous `generated-index.tsv` fingerprints loaded; ISOLATING processors may `reuseGenerated`.
Explain log: `GENERATE` vs `REUSE … unchanged`.

## 14. Processor Graph

Nodes: processors → generated source/resource/metadata under `.jnative/generated/` (0.29 cache path).

## 15. Processor Fingerprints

Include type API shape, processor version, annotation inputs; ABI via `MetaApiVersion`.

## 16. Isolating Processor

`JsonProcessor`, `ValidationProcessor`, `ConfigProcessor`, `EntityProcessor` — per-type outputs.

## 17. Aggregating Processor

`CliProcessor`, `DiProcessor`, `RouteProcessor`, `RpcProcessor` — whole-set tables/graphs.

## 18. Global Processor

Supported via `ProcessorKind.GLOBAL` (reserved; builtins avoid it).

## 19. Diagnostics

`error` / `warning` / `info` with `[JN-META]` prefix and source locations.

## 20. Generated Diagnostics

Headers map generated files back to processor + origin (e.g. `JN-META-1021` for illegal `@JsonField` on static).

## 21. Studio Integration

`GeneratedSymbolIndex`: go-to-generated / go-to-origin from `generated-index.tsv`.
CLI: `jnative processors explain`, `jnative generated`.

## 22. Processor Packages

`packages/json-processor` — `type = processor`, `[processor] entry/min_api/max_api`.

## 23. Package Discovery

Explicit manifest metadata (no classpath scan). Builtins registered in `ProcessorRegistry`.

## 24. Permissions

`READ_PROJECT`, `READ_DECLARED_FILES`, `WRITE_GENERATED`, `NETWORK`, `PROCESS`, `ENVIRONMENT`, `NATIVE`.

## 25. Sandbox

Honest boundary: permission model + restricted API + worker-thread isolation.
Not a full OS sandbox. Defaults deny NETWORK / PROCESS / arbitrary FS.

## 26. Crash Isolation

Processor runs on daemon worker thread; failures → `processor X crashed` without killing host.

## 27. Timeout

`ProcessorScheduler.DEFAULT_TIMEOUT_MS` (30s); timeout → diagnostic, continue.

## 28. Determinism

`--deterministic` flag; processors see `context.deterministic()`; same inputs → same output hashes (tested).

## 29. JSON Processor

`@Json` / `@GenerateJson` → `XxxJsonCodec` + `XxxTypeDescriptor` + JSON Schema. Zero reflection.

## 30. RPC Processor

`RpcProcessor` emits schema + `GeneratedRpcRegistry`; dispatcher/client via existing `RpcCodeGenerator`.

## 31. Validation Processor

`@Validated` + field rules → `XxxValidator` (shared Native/WASM source).

## 32. CLI Processor

`@Command` / `@Option` → aggregating `GeneratedCliParser` (no runtime annotation scan).

## 33. Config Processor

`@Config` / `@Default` → `XxxConfigParser`.

## 34. DI Foundation

`@Service` / `@Inject` → factories + `ApplicationGraph`. No Spring-style runtime container.

## 35. DI Graph

Compile-time graph → generated factories → ordinary constructor/field wiring.

## 36. Scopes

Singleton foundation via static `INSTANCE` in factories; Request/Transient reserved for Web integration.

## 37. ORM Mapping

`@Entity` / `@Id` → `XxxRowMapper` + SQL metadata (not Hibernate).

## 38. SQL Validation

Schema snapshot validation foundation via generated metadata (full DB-snapshot check future).

## 39. Route Generation

`@Controller` / `@Get` / `@Post` → `GeneratedRouteTable` (imperative `app.get` remains available).

## 40. Schema Generation

JSON / RPC / SQL schemas as build artifacts under `schema/`.

## 41. Meta Query API

`findTypesAnnotatedWith`, `findMethodsAnnotatedWith`, `findType`, `isSubtype`, fields/methods/generics.

## 42. Generics

Type models carry `TypeId` / simple names; collection types preserved as declared (0.15 awareness).

## 43. Inheritance

`superClass` / `interfaces` / `isSubtype` on `ProgramModel`.

## 44. Visibility

Field/method visibility available on models; processors respect public API surfaces.

## 45. Package Boundaries

0.30 package graph + processor packages with explicit entry; Meta API does not expose private compiler tables.

## 46. Target Awareness

`ProcessingContext.targetTriple()` / `ProgramModel.targetTriple()`.

## 47. Generated Fingerprints

Artifacts carry input fingerprint + output SHA-256; participate in index like ordinary types.

## 48. Processor ABI

`JNATIVE`-equivalent: `MetaApiVersion.CURRENT` / `minProcessorApi` / `maxProcessorApi`.

## 49. Processor Options

`Map<String,String>` options on context; included in scheduler fingerprint surface.

## 50. CLI

```
jnative processors
jnative processors explain <Type>
jnative generated <Symbol>
jnative <src> --explain-meta --deterministic
```

## 51. Build Explain

`--explain-meta` prints `RUN` / `GENERATE` / `REUSE` / `GC orphan` lines.

## 52. Cache

Content-addressed via fingerprint + output hash under `.jnative/generated/`.

## 53. Orphan Cleanup

`gcOrphans` deletes generated files not present in current artifact set.

## 54. Processing Rounds

Up to `MAX_ROUNDS = 8`; later rounds see newly generated types after re-parse merge.

## 55. Termination

Round limit + `JN-META-1099` cycle diagnostic.

## 56. Ordering

Dependency via generated graph / annotation matching — not alphabetical coupling.

## 57. Macro Boundary

`CompileTimeFunction` reserved. **No arbitrary syntax macros** in 0.32.

## 58. TypeDescriptor

Generated `XxxTypeDescriptor.INSTANCE` — static metadata, not reflection.

## 59. Runtime Metadata

Only explicitly generated schemas/descriptors; default annotations are `COMPILE_TIME`.

## 60. DCE

Unused generated helpers subject to whole-program DCE like ordinary code.

## 61. Binary Size

No metadata LLVM intrinsics; selected schemas only. Benchmark harness: future scale tests.

## 62. Compile Performance

Suite covers cold generate, warm REUSE, single-DTO edit isolation.

## 63. Memory

Worker threads shut down after each processor; artifact lists bounded per compile.

## 64. Unit Tests

`Meta032SuiteTest`: parsing, model, discovery, JSON, DI cycle, permissions, crash, determinism,
package manifest, API compat, multi-processor, incremental REUSE, symbol index.

## 65. JSON E2E

`@Json User` → `UserJsonCodec` implementing `JsonCodec` (stdlib) — zero reflection.

## 66. RPC E2E

`RpcProcessor` + classic `RpcAnalyzer`/`RpcCodeGenerator` over Meta registration.

## 67. Validation E2E

Shared generated validators for Native/WASM targets.

## 68. DI E2E

`ApplicationGraph` + factories; cycle `A→B→A` rejected at compile time.

## 69. CLI E2E

Generated CLI parser artifact (no runtime scan).

## 70. Cross-Target

Generated JNative source is target-agnostic unless processor queries `targetTriple`.

## 71. Security

NETWORK/PROCESS denied by default; write confined to generated root; crash isolation.
**Actual boundary:** permission checks + API surface — not a hardened OS sandbox.

## 72. Determinism Tests

Identical dual clean processor runs → equal `UserJsonCodec` output hashes.

## 73. Regression

Host suite `Meta032SuiteTest` green; prior 0.1–0.31 features unchanged by Meta hook (pre-RPC).

## 74. Known Limitations

- Arbitrary syntax macros: out of scope
- Full OS processor sandbox: foundation only (permissions + worker)
- Request-scoped DI / full SQL schema validation: foundation
- Studio deep UI “Go to Generated” uses index API; richer UX TBD
- Processor packages declare entry; host still ships builtins in-compiler
- Avoid naming user `@Config` types `DatabaseConfig` (collides with Web stdlib)
- Generated JSON codecs also emit `XxxCodec` aliases for 0.28 RPC codegen

### Final Principle

JNative does not ask “what without Java Reflection?”  
It answers: **the compiler already knows the types — generate specialized native code once.**

```
Source Type Information
        ↓
Compile-Time Intelligence
        ↓
Generated Specialized Code
        ↓
Whole-Program Optimization
        ↓
Native Machine Code / WASM
```

**JNative 0.32 PASS**
